prompt: Develop a web app to help our staff handle patient dental charts during daily care.
---

- [ ] User can maintain a patient-specific clinical chart that serves as the longitudinal dental record. System can preserve chart data across multiple encounters.
- [ ] User can view an odontogram-style graphical tooth chart that shows existing, completed, and treatment-planned conditions. System can update the visual chart when procedure status changes.
- [ ] User can chart procedures to specific teeth and tooth surfaces during clinical documentation. System can store procedure code, tooth context, and chart status together.
- [ ] User can update charted procedures when clinical findings change. System can retain audit-relevant history instead of silently overwriting prior entries.
- [ ] System can track procedure statuses across treatment workflow, including planned and completed states. User can review status progression directly from chart views.
- [ ] User can enter chronological progress notes for each encounter. System can sort and display entries in clinically meaningful order for review.
- [ ] User can filter chart and progress-note data by date range, entry type, and provider-facing chart views. System can support focused chart review for specific clinical questions.
- [ ] User can mark dentition state as missing, primary, or permanent on the graphical chart. System can reflect these states consistently across related chart displays.
- [ ] User can record tooth movement findings in the chart when clinically relevant. System can visualize movement annotations in the tooth chart context.
- [ ] User can associate treatment-planned procedures with planned appointments. System can support multi-visit treatment organization from charted items.
- [ ] User can enter and review periodontal chart data as part of routine clinical charting. System can present perio information as structured clinical measurements.
- [ ] User can create prescription records from chart workflow, including single and multi-prescription paths. System can support e-prescription integration and prescription status visibility.
- [ ] User can view pending prescriptions, refill requests, and prescription transmission errors. System can expose these medication workflow states in chart-accessible controls.
- [ ] User can create lab cases linked to charted treatment. System can keep lab workflow tied to the patient’s clinical context.
- [ ] User can attach and review consent documentation from chart module workflow. System can keep consent records available alongside treatment documentation.
- [ ] User can create exam-sheet style clinical assessments from the chart toolbar. System can store these assessments as part of the patient’s clinical record.
- [ ] System can display core patient demographics and medical summary information adjacent to charting workspace. User can open detailed patient or medical records directly from summary rows.
- [ ] User can print progress notes in a print-ready clinical format. System can include encounter-oriented metadata such as date/signature lines when configured.
- [ ] User can save tooth-chart visuals to imaging/document areas for recordkeeping. System can support image-category access inside chart module for clinical review.
- [ ] System can record who performed chart actions and when they occurred. User can refresh chart state to ensure the latest clinical documentation is visible.
